# arXiv スワイプアプリ 再現仕様書（AI コーディングエージェント向け）

この文書は、Claude Code や Codex などのコーディングエージェントに渡し、
**ga-swipe（arXiv 新着をスマホでスワイプして仕分けるアプリ）と同等のものを、別の人の環境で一から作らせる**ための仕様書です。
人間が読んでも分かるように書いていますが、主な読み手はエージェントです。

参照実装（公開リポジトリ）: https://github.com/KNakashima37/ga-swipe
迷ったらこのリポジトリのコードを読んで挙動を合わせてください。ただし、カテゴリ名・URL・キー類はそのまま流用しないこと。

---

## 0. エージェントへの指示（最初に読むこと）

1. **実装に入る前に、§2 の「決めること」をユーザーに質問して確定させる。** 特にカテゴリと翻訳エンジンは構成全体に影響する。
2. 参照実装を `git clone` して読むのは自由。ただし最終的な成果物は、ユーザー自身の新しいリポジトリに置く（fork ではなく新規作成を推奨。自動コミット履歴を引き継がないため）。
3. 人間にしかできない操作（GitHub の Secrets 登録、Pages の有効化、Cloudflare へのログイン、翻訳 API の契約とキー取得）は、手順を具体的に提示してユーザーに実行してもらう。キーを受け取ってファイルに書き込むことはしない。
4. §9 の受け入れ基準をすべて満たしたら完了とする。

## 1. 完成形の概要

- arXiv の指定カテゴリの新着論文を、スマホのブラウザで **左スワイプ＝見送り、右スワイプ＝気になる（保存）** で仕分ける個人用ツール。
- タイトルは自動で日本語訳済み。アブストは原文表示で、「本文を翻訳」をタップしたときだけ訳を取得する。
- PC 作業は不要。GitHub Actions が毎日 arXiv を取得・翻訳して `latest.json` をコミットし、GitHub Pages が配信する。スマホではページを開く（再読み込みする）だけ。
- 既読・保存はスマホのブラウザ（localStorage）にのみ記録し、サーバーには送らない。
- 費用は原則ゼロ（GitHub Public リポジトリ、Cloudflare Workers 無料枠、翻訳 API の無料枠の範囲内）。

### 構成

```
GitHub Actions(毎日) ─→ arXiv API 取得 ─→ 翻訳APIでタイトル翻訳 ─→ latest.json / usage.json をコミット
                                                                         │
                                              GitHub Pages で配信 ◀──────┘
                                                     │
                                              スマホで開く ─(本文タップ翻訳時のみ)─→ Cloudflare Worker ─→ 翻訳API
```

### ファイル構成（参照実装）

| ファイル | 役割 |
|---|---|
| `index.html` | スワイプ UI 本体。単一ファイル、ビルド不要、外部依存は MathJax（CDN）のみ |
| `ga_fetch.py` | arXiv 取得、タイトル翻訳、翻訳キャッシュ、使用量取得、`latest.json` 生成 |
| `.github/workflows/update.yml` | 毎日 `ga_fetch.py` を実行し、成果物を検証してコミット |
| `latest.json` | 直近 7 日の新着（自動生成） |
| `usage.json` | 翻訳 API の当月使用量（自動生成、任意機能） |
| `ga_swipe/cache.json` | タイトル翻訳キャッシュ（コミット対象） |
| `tests/test_ga_fetch.py` | `ga_fetch.py` の単体テスト（32 件、ネット不要） |
| `worker/` | 本文ワンタップ翻訳を中継する Cloudflare Worker。翻訳 API キーはここにだけ置く |
| `icon.png` | ホーム画面アイコン（ユーザーが用意） |

## 2. 決めること（実装前にユーザーへ確認する）

| 項目 | 参照実装の値 | 確認すること |
|---|---|---|
| arXiv カテゴリ | `astro-ph.GA` | 1 つか複数か。複数なら `cat:A OR cat:B` で取得する（§6） |
| 翻訳エンジン | DeepL API Free | §5 の候補から選ぶ。翻訳不要（英語のまま）も選択肢 |
| 翻訳先言語 | 日本語 | 通常は日本語のまま |
| 本文ワンタップ翻訳 | あり（Cloudflare Worker） | 不要なら Worker を丸ごと省略できる。その場合ボタンも消す |
| 使用量表示 | DeepL の当月使用文字数 | 選んだ API に使用量取得 API が無ければ省略 |
| 取得窓 | 直近 7 日 | 新着数が多いカテゴリでは短くする（§6） |
| 実行時刻 | 毎日 21:00 UTC（06:00 JST） | arXiv の公開は日本時間の朝。変更不要なことが多い |
| アプリ名・リポジトリ名 | GA-Swipe / `ga-swipe` | 名前に合わせて `ga_` 接頭辞や表示名を変える |
| GitHub ユーザー名 | なし | Pages の URL（`https://<user>.github.io/<repo>/`）と CORS 許可元に使う |

## 3. データ形式

### `latest.json`（配列。各要素が 1 論文）

```json
{
  "id": "2607.06541",
  "version": "v1",
  "title": "原文タイトル（$...$ の TeX を含みうる）",
  "abstract": "原文アブスト",
  "authors": ["A. Author", "B. Author"],
  "primary": "astro-ph.GA",
  "cross": ["astro-ph.SR"],
  "comment": "14 pages, accepted by ApJ",
  "published": "2026-07-08",
  "updated": "2026-07-08",
  "abs_url": "https://arxiv.org/abs/2607.06541",
  "pdf_url": "https://arxiv.org/pdf/2607.06541",
  "title_ja": "日本語タイトル",
  "abstract_ja": ""
}
```

- `id` は版番号を除いたベース ID。同じベース ID は 1 件にまとめる（クロスリストや版違いの重複排除）。
- `abstract_ja` は Actions では空文字（タイトルのみ翻訳のため）。アプリ側でタップ翻訳した結果が入る。
- 参照実装の astro-ph.GA では 7 日分でおよそ 110 件。

### `ga_swipe/cache.json`（翻訳キャッシュ）

キーは `"{engine}:{id}:{field}"`（例: `"deepl:2606.17008:title"`）、値は訳文。
**エンジン名をキーに含めるので、エンジンを替えると既存キャッシュは使われず再翻訳になる。** 初回はそれを見込む。

### `usage.json`（任意）

```json
{ "character_count": 15756, "character_limit": 500000, "percent": 3.15, "updated": "2026-07-08T13:02:11Z" }
```

## 4. コンポーネント仕様

各項目の「落とし穴」は、参照実装で実際に不具合が出て直したものです。必ず踏襲してください。

### 4.1 取得・翻訳スクリプト（`ga_fetch.py` 相当、Python 3.11、依存は `feedparser` と翻訳 SDK のみ）

主な CLI オプション:

| オプション | 意味 |
|---|---|
| `--category` | 取得カテゴリ |
| `--engine` | 翻訳エンジン（`none` / 選んだエンジン名） |
| `--days N` | 状態ファイルを無視して直近 N 日を取得 |
| `--max` | 取得上限（既定 200） |
| `--min-results` | `--days` が 3 以上で取得件数がこれ未満なら異常終了（既定 10、0 で無効） |
| `--limit N` | 翻訳する件数の上限（無料枠の節約用） |
| `--title-only` | タイトルのみ翻訳 |
| `--ignore-seen` | 既出 ID も出力（Actions では常に付ける） |
| `--usage` / `--usage-out PATH` | 使用量を表示 / JSON に書き出す |
| `--selftest` | ネット不要の自己テスト |
| `--contact` | arXiv へ送る連絡先（環境変数 `GA_CONTACT` でも可） |

arXiv API の使い方:

- エンドポイント `https://export.arxiv.org/api/query`、`search_query=cat:<カテゴリ>`、`sortBy=submittedDate`、`sortOrder=descending`、1 ページ 100 件。
- `User-Agent` に連絡先を入れる（例: `myapp/0.1 (mailto:you@example.com)`）。
- ページ間は 3 秒以上あける。
- `published` が取得窓の開始より古くなった時点で打ち切る（降順なので以降は全部古い）。

落とし穴:

1. **arXiv API は一時的に空の応答や短いページを返すことがある。** 空応答と HTTP エラーは 5 秒あけて最大 3 回再試行する。**要求より短いページが来ても打ち切らない**（次のページが空かどうかで末尾を判定する）。
2. **API 不調で取得が極端に少ないとき、成果物を上書きしない。** `--days >= 3` で件数が `--min-results` 未満なら終了コード非 0 で止める。ワークフロー側でも件数を検証する（二重ガード）。スマホ側は `latest.json` が空だとカードが全部消えるため。
3. **JSON の保存は一時ファイルに書いてから `os.replace` で差し替える**（中断時に元ファイルを壊さない）。また保存先がディレクトリ無しのファイル名（`usage.json` など）のとき `os.makedirs("")` が例外になるので、ディレクトリ名が空なら作成を飛ばす。
4. 既出 ID リスト（`state.json`）は古い方から捨てて 3000 件に保つ。`state.json` はコミットしない（`.gitignore`）。
5. **TeX 数式の保護。** `$$...$$` と `$...$` を ` ZMATH0Z ` のような記号に置き換えてから翻訳し、訳文で元に戻す。戻すときは前後の空白と大文字小文字の揺れを許す（正規表現 `\s*ZMATH{i}Z\s*`、大文字小文字無視）。番号が 10 以上でも衝突しないこと。
6. 翻訳失敗時は空文字を入れ、**キャッシュには保存しない**（次回再試行させる）。

翻訳エンジンは次のインターフェースのクラスで差し替え可能にする:

```python
class Translator:
    name: str                      # キャッシュキーに使う
    def translate(self, text: str) -> str: ...
    def usage(self) -> tuple[int, int]: ...   # 任意。(使用量, 上限)
```

出力は `ga_swipe/out/latest.json`（ほか確認用に Markdown / HTML のダイジェスト）。ワークフローでこれをリポジトリ直下にコピーする。

### 4.2 GitHub Actions（`.github/workflows/update.yml`）

- トリガー: `schedule`（毎日 1 回）と `workflow_dispatch`（手動実行）。
- `permissions: contents: write`。
- 手順: checkout → Python 3.11 → **依存をバージョン固定で** pip install → 単体テスト → 取得・翻訳（`--title-only --days 7 --ignore-seen --usage-out usage.json`）→ `latest.json` の件数と `usage.json` の形を検証 → コミットして push。
- 落とし穴:
  - `usage.json` は翻訳 API の障害時に書き出されないことがある。**存在するときだけ `git add` する**（無条件に add すると、ファイルが無い日に `latest.json` のコミットまで止まる）。
  - push 前に `git pull --rebase origin main` を入れる（ジョブ実行中に手動 push があっても衝突させない）。
  - `git commit ... || echo "no changes"` で変更なしの日も失敗扱いにしない。
- Secrets: 翻訳 API キー（参照実装では `DEEPL_API_KEY`）と `GA_CONTACT`。

### 4.3 スワイプ UI（`index.html`）

単一 HTML、フレームワークなし、ビルドなし。参照実装を読んでそのまま構造を真似るのが早い。

機能:

- 起動時に `./latest.json` と `./usage.json` を `cache: 'no-store'` で取得。失敗時はファイル選択で JSON を読み込める。
- カード: カテゴリ、ID、日本語タイトル（下に原題）、著者（先頭 3 名＋「ほか」）、日付とコメント、アブスト（カード内で縦スクロール）、abs / PDF リンク。
- 操作: 左スワイプまたは ✕＝見送り（既読）、右スワイプまたは ♥＝気になる（既読＋保存）、中央ボタン＝arXiv の abs を開く（仕分けはしない）、「元に戻す」＝何段階でも取り消し。
- 本文翻訳ボタン: 未翻訳なら「本文を翻訳」、翻訳済みなら「原文を見る」と「日本語訳を見る」の切り替え。
- 保存リスト画面: Markdown 形式でコピー、BibTeX 形式でコピー、バックアップの書き出しと読み込み。
- 使用量表示: ヘッダー付近に小さく表示し、80% 以上で警告色。`usage.json` が無ければ非表示。
- 数式は MathJax 3（CDN、バージョン固定）で `$...$` を描画。
- iOS のホーム画面追加用メタタグ（`apple-mobile-web-app-capable` など）と `apple-touch-icon`。

localStorage のキー（接頭辞はアプリ名に合わせて変えてよい）:

| キー | 中身 |
|---|---|
| `gaswipe_read` | 既読 ID の配列 |
| `gaswipe_kept` | 保存した論文オブジェクトの配列 |
| `gaswipe_absja` | `{ id: アブスト訳文 }` 本文翻訳の端末内キャッシュ |

落とし穴:

1. **スワイプとアブストの縦スクロールの両立。** `pointerdown` ではポインタをキャプチャしない。移動量が 8px を超えた時点で、横が縦より大きければ横スワイプとして確定し、そこで初めて `setPointerCapture` する。縦が先に 8px を超えたらスワイプ処理をやめてスクロールに任せる。確定の閾値は横 120px。
2. **連打による誤仕分けの防止。** カードが飛んでいくアニメーション中（約 230ms）はフラグを立て、次のスワイプ、ボタン、「元に戻す」を受け付けない。
3. ボタンやリンク上での `pointerdown` はスワイプとして扱わない。
4. **既読の無限増加を防ぐ。** 自動読み込みに成功したときだけ、現在の `latest.json` に無い ID を既読リストと本文翻訳キャッシュから削除する。保存リストには触れない。手動でファイルを読み込んだときは削除しない（古い JSON を開いたときに既読が消えるため）。
5. **バックアップの読み込みは上書きではなく追加マージ。** 同じ ID は重複追加しない（同じファイルを何度読み込んでも安全）。
6. 表示する文字列はすべて HTML エスケープし、リンクは `http(s)://` で始まるものだけ許可する（手動読み込みした JSON への対策）。
7. **iOS では、ホーム画面に追加した Web アプリと Safari の通常タブは localStorage が別。** またホーム画面のショートカットを削除すると、そのデータには戻れない。アイコンを作り直すときは、先にバックアップを書き出すよう README に書いておく。

### 4.4 本文ワンタップ翻訳の中継（Cloudflare Worker、任意）

翻訳 API キーをスマホ側のコードに置けないため、Worker が中継する。

- `POST /translate`: `{ text, id }` を受け取り `{ id, text_ja, cached }` を返す。
- `GET /usage`: 当月使用量（予備。通常は Actions の `usage.json` で足りる）。
- KV `TRANSLATE_CACHE`: キー `abs:<id>` に訳文を永続保存。同じ論文は他の端末から読んでも二度翻訳しない。
- KV `RATE_LIMIT_KV`: 同一 IP につき 60 秒あたり 20 リクエストまで。KV 未設定なら制限なしで動かす。
- CORS: 環境変数 `ALLOWED_ORIGIN`（例 `https://<user>.github.io`）と一致する Origin だけ許可。大文字小文字は区別せず比較。不一致は 403。
- 入力検証: `text` は空でなく 6000 文字以下、`id` は `^\d{4}\.\d{4,5}$`。
- **翻訳 API のエラー内容をそのままクライアントに返さない**（キーを含みうるため）。502 と固定のエラーコードだけ返す。
- キーは `wrangler secret put <名前>` で登録し、`wrangler.toml` やリポジトリには書かない。

落とし穴:

- `wrangler.toml` の `kv_namespaces` はトップレベルのキーなので、**`[vars]` より前に書く**。後ろに書くと TOML の仕様上 `[vars]` の中身として解釈され、KV が無いことになる。
- KV 作成コマンドは wrangler 3 系が `wrangler kv:namespace create NAME`、4 系が `wrangler kv namespace create NAME`。
- デプロイ後に払い出される URL を `index.html` の `WORKER_URL` 定数に書く。

## 5. 翻訳エンジンの選び方と差し替え箇所

参照実装は DeepL API Free（月 50 万文字まで無料、無料キーは末尾 `:fx` で、API のホストが `api-free.deepl.com` になる）。
他のエンジンにする場合の候補と注意点:

| 候補 | 向いている場合 | 注意点 |
|---|---|---|
| DeepL API Free | 参照実装と同じでよい | 新着の多いカテゴリでは無料枠を超えうる（§6） |
| Google Cloud Translation / Azure Translator | 無料枠の大きいクラウド翻訳を使いたい | 課金アカウント登録が必要なことが多い。無料枠の条件は契約時に確認 |
| LLM API（Claude、OpenAI、Gemini など） | 専門用語の訳を良くしたい、要約もさせたい | 文字数ではなくトークン課金。使用量 API が無いので `usage.json` は自前で文字数を数えるか省略。プロンプトで「TeX と記号 ZMATHnZ はそのまま残す」と指示する |
| Cloudflare Workers AI の翻訳モデル | Worker 側でキー管理を省きたい | 英日翻訳の品質は要確認。Actions 側（タイトル翻訳）には別途 API 経由で使う |
| 翻訳なし（`--engine none`） | 英語のままで困らない | Worker、使用量表示、Secrets がまるごと不要になり、最も簡単 |

**無料枠や料金は変わるので、エージェントは数字を記憶で断定せず、ユーザーに公式ページで確認してもらうこと。**

差し替え時に変更する箇所:

1. `ga_fetch.py`: §4.1 のインターフェースで新しい Translator クラスを足し、`--engine` の選択肢に加える。数式マスクは必ず通す。
2. ワークフロー: pip の依存（バージョン固定）、Secrets 名、`--engine` の値。
3. Worker: `deeplTranslate` 相当の関数を差し替え。キーの secret 名も合わせる。
4. 使用量表示: 取得 API が無ければ `--usage-out` とアプリ側の表示を外す（`usage.json` が無くてもアプリは動く作りにしておく）。
5. テスト: 翻訳 API はモックに差し替えて、キャッシュ、失敗時、`--limit`、`--title-only` の挙動を確認する。

## 6. カテゴリを変えるときの注意

- **新着数がカテゴリで大きく違う。** astro-ph.GA は 7 日でおよそ 110 件だが、cs.LG や cs.CV などは 1 日で数百件ある。その場合:
  - `--max`（既定 200）を超えると古い側が切れるので、取得窓（`--days`）を短くするか `--max` を上げる。arXiv 側は 1 ページ 100 件、3 秒間隔なので、件数が増えると取得に時間がかかる。
  - タイトル翻訳の量が増える。1 タイトルを 100 文字程度と見積もり、`1 日の新着数 × 100 × 30` が月の無料枠に収まるかを確認する。
  - スマホで毎日さばける件数かどうかもユーザーと相談する（サブカテゴリに絞る、など）。
- **件数が少ないカテゴリ**では `--min-results`（既定 10）とワークフローの件数検証（10 件以上）を下げないと、正常な日に異常終了する。
- 複数カテゴリは `search_query=cat:A OR cat:B` で 1 回の問い合わせにできる。ベース ID での重複排除が効くので、両方に載る論文も 1 件になる。
- `id` の正規表現（`^\d{4}\.\d{4,5}$`）は新形式の arXiv ID 専用。新着だけを扱う限り問題ない。
- 名前の `ga` はカテゴリ名由来なので、スクリプト名、作業ディレクトリ、localStorage の接頭辞、User-Agent、表示名を新しいアプリ名に置き換える。

## 7. テスト

`tests/` に `unittest` で書く（ネット不要、翻訳 API と arXiv はモック）。参照実装にある 32 件の観点:

- arXiv の Atom を正しく整形できる / ID の形式が不正なら捨てる / 公開日が無いエントリを捨てる
- 数式マスクの往復、10 個以上の数式で番号が衝突しない、戻す際の大文字小文字の揺れ
- 翻訳とキャッシュ: キャッシュがあれば API を呼ばない、失敗時は空でキャッシュしない、`--limit 0` はキャッシュのみ、`--title-only` でアブストを訳さない
- 取得: HTTP エラーや空応答の後に再試行して成功する、再試行しても空なら空を返す、エラーが続けば例外、短いページで打ち切らない、取得窓の境界で止まる、クロスリストと版違いの重複排除
- 件数ガード: 窓が広く件数が少ないと発動、十分なら発動しない、窓が狭いときや閾値 0 では発動しない
- 既出 ID の追記と重複排除、上限超過時に古い方から捨てる
- JSON 保存: 往復、ディレクトリ無しのファイル名、書き込み中断で元ファイルが残る、壊れた/無いファイルは既定値を返す
- 使用量: 割合の計算と時刻の形式、上限 0 で割り算しない

## 8. デプロイ手順（ユーザーが行う操作をエージェントが案内する）

1. GitHub に **Public** リポジトリを新規作成（無料の Pages と Actions のため。中身は arXiv の公開メタデータのみ）。
2. **Settings → Secrets and variables → Actions** で翻訳 API キーと `GA_CONTACT`（連絡先メール）を登録。
3. コードを push し、**Actions** タブでワークフローを一度手動実行（Run workflow）して `latest.json` を生成。
4. **Settings → Pages** で Source を「Deploy from a branch」、Branch を `main` と `/(root)` にして保存。
5. （本文翻訳を使う場合）Cloudflare アカウント作成 → `wrangler login` → KV を 2 つ作成し ID を `wrangler.toml` へ → `ALLOWED_ORIGIN` を自分の Pages のオリジンに → `wrangler secret put <キー名>` → `wrangler deploy` → 払い出された URL を `index.html` の `WORKER_URL` に書いてコミット。
6. スマホの Safari で `https://<user>.github.io/<repo>/` を開き、共有メニューから「ホーム画面に追加」。以後は必ずホーム画面のアイコンから開く。

## 10. 既知の限界（参照実装と同じ。直さなくてよい）

- 投稿日基準で取得するため、過去に投稿されて最近クロスリストされた論文は一部拾えない。改訂版（v2 以降）は新着として再表示しない。
- Worker のレート制限は KV ベースなので厳密ではない（連打防止としては十分）。
- 既読と保存は端末ごと。複数端末間の同期はしない（バックアップ JSON で手動移行）。
